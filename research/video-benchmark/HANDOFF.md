## 3. 三处真 bug / 真限制

### 3.1 装配器会把两次组队折成一次（已修，已加回归测试）

第 1 轮第 2 次组队的板面「否决组队」被水印吃掉，于是这一行有车队、有完整票型，**没有结果**。下一行（第 3 次、强制轮）报到时，`blocks.py` 走了「把当前空块改号成板面行」那条分支——可那个块**不空**，它就是第 2 次组队。结果：两次组队折成一个 `b1-3`，而且是个**带票型的强制轮**，桌上不可能出现的东西，被 `validate.py` 挡下。

修法：只有当开着的块**没有自己的板面行**（无车队 / 票型 / 结果 / 车主）时才允许改号；否则新开一个块，让前一次组队保留自己的行并且**结果留空**。

```
tests/test_agent_blocks.py::test_an_attempt_whose_result_phrase_was_occluded_keeps_its_own_block
```

**扫过历史：39 份 audit.json 里 0 份走过改号分支，所以前三局的产物不受影响**（80 个哈希也确实一个没变）。

渲染出来是：`车主：1号 / 车队：1、6、7 / 上票：1 / 下票：2…10 / 组队结果：未记录`。**没有从票型反推结果**，哪怕票型是完整的。

### 3.2 `final_outcome` 原来是手改进文件的，重建就没了（已修）

`build_roster_v2()` 从来不产出 `final_outcome`，第一局（`src-fe54eb89f162`）那份是生成后手工塞进去的——下次重建私有名单就会被冲掉。现在它和 `reveal_note` 一样是个参数，CLI 加了 `--final-outcome <json>`。

第四局因此补上了：客户端 2175.72 s 的字幕「本场游戏 莫德雷德的爪牙阵营胜利」是**公开**宣布的胜负，`winning_side = evil`；三轮任务全挂、坏人按任务取胜、**没有刺杀环节**，所以刺杀两项不是「未记录」而是「没有发生」，basis 里写清楚了。顺带修了 roster 笔记把这条字幕写成 1775.75 s 的笔误（实际 2175.72）。

### 3.4 板面被盖住的行，现在有了「公告补录」的数据入口（新建，已用上）

上一条留下的窟窿补了。`board.apply_supplements()` 允许在配置里写下**客户端自己播报过什么、在第几秒**，据此补出一个 `source: "manual"` 的事件。三条硬规矩写进了实现和测试：

- **重跑同一条是空操作，改口不是。** payload 变了还想靠重跑写进去，同样抛错——改口走修正链。
- **补录事件照样 `needs_review` 且未锚定**，和板面事件走同一道人审关口。

配套加了 `python -m vbench board-supplements`：只动 `public/events.jsonl`，**不重新解码、不重新 OCR**。重跑 `extract` 能得到同样结果，但那要 19 分钟去改文件里的两行。

**但它只进了 full 样本，没进三个截止点样本**，而且这是对的：账本给它分配的序号是 1151（最后一个），按 `ledger.py` 那条「只会晚、不会早」的规则，早于它的截止点不收。三个 m1/m2 截止点里这一次组队仍写「组队结果：未记录」，票型仍是完整的十个座位。要让截止点也带上它，只能整份重建账本再出一个修订，**不能就地改号**——这句话写进了 r1 的 `open_questions`。
