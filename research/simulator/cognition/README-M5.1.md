## 一、起因：M5 试点的两个发现

那一局（`g-a0b76ac9`，$6.9745，坏人 3:0）跑完了，运行时全部指标干净。但它暴露了两件事。

### 1. 前提校验机制是空转的

提示写着「`factsUsed`：你用到的硬事实 id（就是上面事实表里 `f` 开头的那些）」，
**而事实表根本没有渲染任何 id**。模型只剩两条路：编一个看起来合理的
（`f_private_8_percival_pair_7_9`、`f_current_state`），或者写好 `premiseLabels`
然后把 `premiseIds` 留空。

后果：**871 条引用全部被判为未证实**，144/154 个响应带着未证实约束。
账本存在的全部意义 —— 分开「裁判记录」和「某人的话」—— 在那一局里塌成了「一切都不硬」。

而且这也是那局五次重问的直接原因（见第四节）。

### 2. 牌桌变安静了

私下推理变好了，公开协调变差了：明确接住或反驳别人论证的发言从 48% 掉到 21%，
**全场零次跳身份**，好人从头到尾没有形成过任何联盟。坏人不需要拆联盟，因为没有联盟。

十个各自正确的私下分析，打不过四个协调好的人。

## 二、事实 ID 管道（`cognition/fact-ids.ts`）

一个 registry，每个座位每一步各建一份，从**渲染事实表用的同一批裁判数据**建出来，
并且**印在每一行前面**。

```markdown
### 当前局面 `[f.now]`
### 任务结果
- `[f23]` 第 1 轮 失败　上车 8、1、3号　公开失败票 1
### 提案与投票
- `[f9]` R1#1 8号发车 8、1、3号
    `[f11]` 车过了　反对：4、5号
### 湖中女神
- `[f34]`／宣称 `[c34:lady]` 9号 验了 1号，**公开宣称**「good」（这是他说的，不是裁判说的）

## 只有你知道的硬信息
`[p.self]` 你是 8号，身份 percival。
`[p.pair]` 7、9号 这两个人里，一个是梅林，一个是莫甘娜，你分不出哪个是哪个。
```

三个不变量，各有测试：

| | |
|---|---|
| **公开 id 全桌一致** | 来自事件 sequence，所以两个座位可以互相引用对方的前提 |
| **私有 id 只发给有资格的座位** | 无权座位就算猜到 `p.pair` 这个字符串，自己的 registry 里也没有 |
| **确定性** | 纯函数于 sequence 与自己的 observation —— 重放和 resume 铸出同一批 id |

**女神公布有两个 id**：`[f34]`（裁判记录了这次公布）和 `[c34:lady]`（他说的内容）。
把前者当成后者，就是实验 3 输掉那局的那次坍塌。

「查不到」不区分「拼错」「过期」「编造」「越权」—— 后果都一样（前提不硬），
而一个能区分越权和不存在的接口，就是一个能探测别人私有事实的接口。

## 三、桌面协调（`cognition/social.ts` + 协议层第 15–20 步）

每个座位的账本多了一块**有界的**社会模型：谁在带节奏、跟不跟、以及**公开要说什么别人才能配合**。

四件它刻意不是的事：

- **不是全局领袖分。** 十份读法互不汇总。两个座位对「谁是焦点」有分歧是真实的桌面状态。
- **不是服从。** `follow` 只是四种站位之一，每个候选都同时要写「可以跟」和「可以驳」，
  `conditionToReconsider` 是必填 —— 说不出什么会让自己停下来的，不叫决定。
- **不是身份真相。** `claimedRole` 是他**说**的。`basisIds` 走和前提一样的 registry。
- **不是公开的。** 座位私有，进检查点，公开回放里逐字段扫描断言不出现。

协议层新增的六步（在**缓存的 system 层**，全局唯一一份）：

```
15. 现在谁在带节奏？
16. 他到底要大家接受哪一句话？
17. 支持这句话的最强公开证据是什么？
18. 反对它的最强理由是什么？
19. 你要跟、有条件地跟、驳、还是自己走？
20. 你要在公开场合说什么或做什么，别人才能和你配合？
```

跟的时候要**点名 + 复述具体结论 + 给出票**，「我同意」不产生共同知识。
驳的时候要指出**不接受哪一条前提**。带节奏的时候要给**可执行的请求**。

**但不是每一条怀疑都要说出口** —— 梅林要藏，坏人要掩护。协议明确写了这一条。

## 四、那五次「裁判判非法」其实不是

M5 试点的报告写着「4 票 + 1 发言被裁判判非法」。**一次都不是。**

把那局重放到每一个决策点、再把当时记录的原始回答重新提交给裁判，五次全部合法通过。
真正的原因（`scripts/why-reasked.ts` 打出来的）：

| 次数 | 座位 | 真实原因 |
|---|---|---|
| 4 | 8、4、5、10 | `constraints[0].premiseIds` **是空数组** |
| 1 | 6 | `hypotheses` 的 `label` 和 `rationale` **都是空字符串** |

第一类正是第一节那个缺陷的直接后果：8 号写出了质量很好的 `premiseLabels`
（「裁判记录：R1#1正式车为8、1、3」），然后把 id 数组留空 —— 因为**没有 id 可抄**。

根因分类：

- **schema 太宽松**：`premiseIds` 没有 `minItems`，`label` 没有 `minLength`。
  模型完全遵守了 schema，然后被解析器拒绝，白花一次请求。
- **提示有错**：指向了不存在的 id。
- **不是裁判规则的问题** —— 裁判规则一个字都没放松。

修法：
1. 事实表渲染 id（第二节）。
2. 0.3.1 的 schema 加上 `premiseIds.minItems = 1` 和 `label/rationale.minLength = 1`，
   让 provider 先拒，而不是花一次请求才知道。
3. `live-game.ts` 以前把裁判给的理由**丢掉了**，所以产物里查不到原因。
   现在记 `rejectedBy`（referee / cognition / action-format）和 `rejectionReason`。

0.3.0 的 schema 和它的重问提示原文**都不动** —— 那些字节已经发出去过了。

## 五、上限调整

| | 0.3.0（已冻结） | 0.3.1 | 依据 |
|---|---|---|---|
| `maxHypotheses` | 4 | **6** | 试点里十个座位峰值全部顶到 4/4 |
| `maxPublicCommitments` | 8 | **12** | 同样 8/8，而且溢出时**静默丢掉最老的承诺** |
| `maxOutputTokens` | 20,000 | **12,000** | 实测峰值 5,511（27.6%）—— 20,000 是按一个高估约 7 倍的预检定的 |
| 证据 / 约束字数 | 不动 | 不动 | 峰值只有 21% 和 33%，没有测量支持改动 |

承诺的生命周期也改了：关掉一条现在是一个**明确动作**（`closedCommitments`，
带 fulfilled / obsolete / withdrawn），不再是数组溢出的副作用。
以前一个座位只要多说八句话，就能悄悄不再对开场那句负责。

## 六、被冻住的东西

| | 状态 |
|---|---|
| `config/default.json` | 一个字节没动（prompt-0.2.0 / baseline / cognition false）|
| `config/m5-pilot.json` | 一个字节没动（prompt-0.3.0 / expert-cognitive / 20,000）|
| `COGNITION_LIMITS`（0.3.0 的表） | 冻结，新数字全部在 `COGNITION_LIMITS_V2` |
| `COGNITION_FRAGMENT`（0.3.0 的 schema） | 冻结，由 `cognitionFragment(V1)` 生成 |
| `DECISION_PROTOCOL_LAYER`（十四步） | 冻结，新的六步在 `PUBLIC_BRIDGE_LAYER` |
| `baseline` / `community-meta` / `expert-cognitive` 指纹 | 全部未变（有测试断言）|
| 裁判规则 | 一条都没放松 |

`expert-social` 是**新档**，spread 了 `expert-cognitive` 的全部条目再追加。
测试断言继承的是**同一批对象**（`toBe`，不是 `toEqual`），所以两者不可能悄悄分叉。

`prompt-0.3.1` 与 `expert-social` 是**一一绑定**的：拆开重组会被配置校验拒绝。

## 七、还没验证的东西

- **压缩路径仍然没有被真实触发过。** `olderArguments` 在两局里都是 0。
  要打满五轮的长局才可能。不是缺陷，是没测过。
- **协调有没有用，一局看不出来。** `metrics.ts` 的十条指标是为**一系列**对局准备的。
- **真实模型会不会引用错 id。** 脚本替身只抄它读到的，所以离线跑出来「查无此 id」为 0，
  那是管道通了，不是模型聪明。这一条只有付费对局能回答，而遥测就是为它准备的。
