## 二、认知账本的骨架

三个所有者，互不重叠：

```
裁判  publicFacts / privateFacts     只能由事件构造，模型碰不到
牌桌  claims                          「某号在某个 sequence 说了什么」，记录不等于相信
模型  constraints / hypotheses /      全部有界，全部带 provenance
      dossiers / self
```

**一条说法永远不会变成事实。** 这不是靠提示里叮嘱，是靠类型：
`CognitionUpdate` 里根本没有 `publicFacts` 字段，而 `applyCognitionUpdate`
每次都从当前 observation **重新推导**裁判那两半，所以就算有人硬转类型塞进来也会被覆盖掉。

### 硬事实 vs 说法：一个完整的例子

实验 3 第 3 轮，6 号说了这段话：

> 「二车两坏，而我明确是好人：我在车上只能出成，且9刚验报好。因此2、3、5恰有两坏；
> 首车8、1、4恰一坏，四坏总数又迫使7、9、10恰一坏。」

在旧结构里，这整段就是一条自由文本的 note。在账本里它拆成四样东西：

| 类别 | 内容 | verified |
|---|---|---|
| **硬事实** | 第 2 轮 `[2,3,5,6]` 失败，公开失败票 **2** | ✅ 裁判记录 |
| **硬事实** | 第 1 轮 `[8,1,4]` 失败，公开失败票 **1** | ✅ 裁判记录 |
| **硬事实** | 9 号在 seq 62 公布了对 6 号的验人结果 | ✅ 裁判记录（**「他公布了」是事实**）|
| **说法** | 6 号自称忠臣 | ❌ 这只是他说的 |
| **说法** | 9 号公布的内容「6 号是好人」为真 | ❌ 这只是他说的 |
| **推论** | 2、3、5 恰有两坏 | **`restsOnUnverified: true`** |

关键在最后一行：`deriveConstraint` **计算**这个标记，不接受模型自己填。
只要有一条前提不是裁判记录，整条结论就是软的 —— 而且渲染时标记是**贴着结论**的，
不是脚注：

```
- 【前提未证实】2、3、5 恰有两坏　依据：第二轮两张失败票、6号自称忠臣(未证实)、9号公布6号是好人(未证实)
```

`ledger.test.ts` 里有一条测试就叫「cannot express Experiment 3's mistake」。

### 模型自称「已验证」也没用

`resolvePremises()` 拿模型给的 `premiseVerified` 和裁判自己的事实表对照，
不一致就以裁判为准并计数。没有这一步，`restsOnUnverified` 就成了模型自证清白。

## 三、派西维尔的例子

实验 3 的 8 号手上是 `{kind: "merlin_or_morgana", pair: [7, 9]}`。第 2 轮他说：

> 「终单含 7、9 同车我必反。」

这在账本里是一条**前提全硬**的推论：

```
- 【前提都是裁判记录】这辆车必含莫甘娜　依据：我自己的候选对(own-role)、R2#1 的提案名单
```

对照实验 2 —— 同一副牌、同一座位（8 号）、同一 persona（challenger）、
唯一不同是策略档 —— 他从头到尾没把 7 和 9 当成一对，最终把莫甘娜推到 **+0.8**、
把梅林推到 **−1.0**，终单带 7 排 9。

**注意：那两局之间同时变了策略档和 `maxOutputTokens`（6000 → 12000），
所以这不是干净的因果证据。** 它是 `scenarios.ts` 里 `s03` 存在的理由：
把这个位置固定下来，将来任何一版 agent 都要在它上面被检验。

`s03` 的设计要点：**认出「这车必含莫甘娜」是强制的，怎么处置不是。**
强烈反对、包装后反对、放行换信息 —— 三条都在可接受族里。

## 四、梅林与女神的例子

`s04`：梅林（9 号）看得见 `[2, 4, 7]`，看不见莫德雷德，手上有女神，2 号和 4 号还没定性。

分析义务（必须做到）：

1. 分清「看得见的 2、4、7」和「看不见的莫德雷德」是两个集合
2. 认识到验 2、4、7 换不到任何新信息
3. 列出未定性座位作为莫德雷德候选
4. 把令牌会转给被验者算进去

可接受的两族：**找莫德雷德** 或 **验已知好人换公开信号 / 令牌去向**。
后者也是专家线 —— 但必须说清放弃搜索换到了什么。

三局的实际情况：第二局梅林验 5 号（忠臣）、实验 3 验 6 号（忠臣），
**两次都验在已知不是可见坏人的座位上，两次都没说换到了什么**。
这条考量在实验 3 里渲染给了梅林，被忽略了。

## 五、坏人双踩的例子

`s09`：刺客（2 号）在车 `[2,3,5,6]` 上，知道队友 3 号也在车上。

实验 3 的实际结果：**两人都踩，2 张失败票**。一张就够挂车，第二张不增加分数，
只把「这车至少两个坏人」免费告诉全桌 —— 而桌面立刻把它变成了后续所有推理的基石
（「二车两坏」在实验 3 的发言里出现了十几次）。

`s09` 给出三条都可接受的线，**没有强制踩牌约定**：

- `coordinate-single-fail` —— 只出一张（要说清没有沟通渠道时怎么降低双踩风险）
- `play-success-for-cover` —— 自己出成功（要说清放过这一轮的代价）
- `double-fail-deliberately` —— 接受双踩（要说清为什么掩护已经不值钱）

`scenarios.test.ts` 有一条测试专门断言这三条都在，防止将来有人把它收窄成一条。

## 六、提示结构：之前 vs 之后

### 之前（M0–M4，现在跑的）

```
system  1 共同规则           固定
        2 说话风格（persona） 只影响文风
        3 身份与合法信息类型   按身份
user    4 你实际看到的东西     完整私有信息
        5 位置与公开局面       **全部历史，逐条原文**
        6 策略档              baseline 空 / community-meta 37 条
        7 本次任务与输出格式
```

实测：实验 3 单次最大 18,099 字符 / 14,706 provider token，
累计输入 1.32M token，其中 **87% 未缓存**。

### 之后（M5 设计）

```
system  1 共同规则           固定
        1.5 决策协议层        **固定，全桌全局共用一份 —— 所以能缓存**
        2 说话风格 + 决策旋钮  影响文风**和**决策倾向
        3 身份与合法信息类型   按身份
user    4 硬事实表            裁判生成，**无损，永不压缩**
        4b 挂车约束           裁判事实算出来的算术，不花推理 token
        5 只有你知道的硬信息   按 side 门控
        6 你自己的推理记录     有界；未证实前提**贴着结论**标注
        7 更早的讨论（压缩）   **只压缩论证，从不压缩事实**
        8 这一次点车的全部发言  原文
        9 本次任务与输出格式
```

三处结构性变化：

1. **协议层是常量**，不含座位、身份、局面 —— 一局约 150 次请求全部命中同一份前缀。
2. **事实变成表格**。同样的信息，表格比散文省得多，而且**可以机械检查完整性**
   （`compactionCompleteness` 读的是**渲染后的文本**，所以「算对了但忘了塞进去」也会被抓到）。
3. **压缩只碰论证**。`compactableEvents` 只返回 `speech` 事件，有测试断言这一点。

### 压缩绝不删的东西

任务队伍 / 结果 / 失败票数、每一次提案与投票、身份声称与改口、女神持有者 / 目标 / 公布、
当前队长 / 方向 / 提案次数、挂车约束、自己的私有硬事实、未解决的前提依赖、自己的公开承诺。

**没有任何硬事实的唯一副本是自由文本摘要。** 摘要错了或丢了，事实表不受影响。

### 压缩不额外花钱

认知更新随**正常动作响应**一起回来（`protocol.ts` 的 `CognitiveResponse`），
不需要单独的摘要调用。一局已经要发 133–192 次请求，再加一倍是不可接受的。

## 七、建议的字段上限

全部在 `cognition/limits.ts`，全部是**未经校准的初稿**。

| 字段 | 上限 |
|---|---|
| 每座正面 / 反面证据 | 各 6 条，每条 80 字 |
| 每座矛盾记录 | 4 条，每条 100 字 |
| 并存假设 | **至少 2，至多 4** |
| 推导约束 | 12 条，每条 140 字，每条最多 6 个前提 |
| 公开承诺 | 8 条，每条 120 字 |
| 身份计划 / 掩护 / 跳牌计划 | 400 / 200 / 200 字 |
| 候选动作比较 | **至少 2，至多 4**，每条 120 字 |
| 更早论证摘要 | 12 条，每条 180 字 |
| **软目标** | 60,000 token（保守估算） |
| **硬上限** | 250,000 token（沿用既有契约） |

「至少 2 个假设」和「至少 2 个候选动作」是**下限**，和上限一样重要：
一个假设就是过早锁定，一个候选动作就不是比较。

**实测参照**：实验 3 单次实报输入峰值 14,706 token，离 60,000 软目标还有 4 倍。
所以这些上限**当前不是瓶颈** —— 它们是为了防止认知状态无界增长而设的护栏。

## 八、fused vs two-pass

| | fused | two-pass-critical |
|---|---|---|
| 调用数 | 1 次/决策 | 关键任务 2 次，其余 1 次 |
| 输入 | 1× | **关键任务约 2×**（两次都带同样的历史）|
| 分析可见性 | 只有结论 | 分析独立可审、可复用 |
| 实现 | 现在的 agent 加一个结构化字段 | 需要新的请求编排 |

**按实验 3 的形状估算**（6 次提案、挂车后的 6 轮投票、1 次女神、若干跳牌）：
调用数约 133 → 151，**调用成本不是问题**。问题是那 ~18 个决策的**输入付两遍**，
而输入占这一局未缓存开销的 87%。

**这是一个 seed、一局对局的外推，不是推荐。**

两种都没启用。`CognitionMode` 在任何地方都没有默认值，
`two-pass-critical` 的 `criticalTasks` 为空时行为和 fused 完全一样 —— 不存在静默默认。

关键任务候选（`modes.ts` 里每条都带理由）：收车定队伍、挂车后的投票、
跳牌 / 对跳、女神选人、刺杀。共同点：**错了在这局之内无法挽回**。
普通发言不在列，因为下一个发言者可以纠正。

## 九、测试

```
cognition/ledger.test.ts        21 项
cognition/context-pack.test.ts  12 项
cognition/leak.test.ts          14 项
cognition/protocol.test.ts      17 项
cognition/scenarios.test.ts     29 项
```

全部零网络（每个文件都把 `globalThis.fetch` 换成会抛异常的桩）。

最重要的一条是**替换实验**：把一个好人座位的 observation 里
`evilRoster` 和 `evilDiscussion` 换成**伪造的**内容，要求渲染出的提示逐字节相同。

> 用伪造值而不是从另一局借，是因为打完的对局这两个字段对所有人都是空的 ——
> 借来的空值什么都注入不了，测试会因为错误的原因通过。伪造值是明确非空的，
> 所以门控确实在做事。另有一条配对测试证明**有权限的座位确实能看到同样的内容**，
> 否则「没泄漏」可能只意味着「这个字段根本没被渲染过」。

发现并修掉的两个真实缺口：

1. `context-pack` 原本按「数组非空」决定要不要渲染坏人密谈，改成按**座位自己的 side** 门控。
2. `ledger` 原本无条件复制 `evilRoster`，改成只有 evil 座位才复制。

两处都是 `observationFor` 之后的**第二道锁** —— 一个手工构造的畸形 observation
现在也无法让好人拿到答案。

## 十、需要你定的事

1. **fused 还是 two-pass？** 见第八节。我倾向先全 fused 跑一局看结构化结论的质量，
   再决定要不要给那 5 类关键任务加第二遍。但这是花钱的决定。

2. **字段上限要不要先校准？** 现在的数字是拍的。可以先跑一局 fused 收集
   模型实际写多少，再定 —— 也可以直接用，反正超了会被 `validateLedger` 报出来而不是静默截断。

3. **persona 旋钮要不要启用？** 启用会让 `heterogeneous-rotated` 变成一个
   **新的**实验臂，和实验 2 / 实验 3 不再可比。是否需要先补一局旧配置的对照？

4. **`community-meta` 和协议层重叠怎么办？** 协议层的第 3、4、7、8 步和
   community-meta 的第 1、2、3、8 组讲的是同一件事。两个都开会不会互相干扰？
   还是把重叠部分从策略档移到协议层、让策略档只保留身份专属的东西？

5. **手册里六个【待人判断】**（见 `expert-playbook-draft.md` 第六节），
   其中最花钱的是第 2 条：要分开「persona 模式」和「策略档」对反对意愿的影响，
   需要补跑 **hetero / baseline / 12000** 一局。

6. **`promptVersion` 什么时候动？** M5 的协议层是新的提示文本，启用时必须升版本。
   建议 `prompt-0.3.0`，并且在同一次提交里升，不要分两步。
