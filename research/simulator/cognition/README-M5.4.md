## 一、根因：一个版本等值判断

`agents/llm-agent.ts` 里的一行：

```ts
const wantsContest = config.promptVersion === PROMPT_VERSION_CONTEST;   // 只认 0.4.0
```

`prompt-0.5.0` 是 `0.4.0` 的**超集** —— 它在 schema 里要 `social` 和 `contest`，模型也答了（strict schema 强制）。但**折叠回答的那一半没被告知 0.5.0 的存在**，于是两块被整段丢掉：

| | 后果 |
|---|---|
| 解析 | `withSocial:false` → 两块被丢弃 |
| 账本 | 从未折叠 → 下一回合渲染的是**空**记录 |
| 注册表 | 没铸 `k…` → 引用 `[k4:claim]` 全部解析成「查无此 id」 |
| 结构检查 | 派权块的一致性检查一次都没跑 |
| 遥测 | 两局实盘 **203 份报告的 `contest` / `social` 全是 `null`** |

**两局都跑完了，产物都通过验证，没有任何东西报错。** 这才是这类缺陷值得一个机制而不是一个修补的原因。

### 修复不是「更好的比较」，是把比较从调用点拿掉

[`prompts/capabilities.ts`](../prompts/capabilities.ts)：版本**声明**自己的能力，代码问 `capabilities.claimContest`。

- **不做字典序比较** —— `"prompt-0.10.0" < "prompt-0.5.0"` 作为字符串是真的。查表没有顺序，这个坑不存在。
- **未声明的版本抛错**，不给「安全默认」。默认就是同一个失败换身衣服：功能开一半，跑到底，产物看起来正常。
- 五行冻结行描述四局已完成对局实际跑的东西。

`separatesStages()` 被**删掉了** —— 它本身就是这个被移除的模式。

## 二、坏人任务牌协调（房规，不是规则）

[`core/evil-coordination.ts`](../core/evil-coordination.ts)

seed 1 的第二轮：四人车需要 1 张失败票，开出了 **3 张**。三个互认的坏人各自决定破坏，裁判把「1–4 里至少 3 个坏」写进事实表，好人靠这条算术赢了整局。**不协调的破坏不是更凶，是在公开报数。**

优先级是 **莫德雷德 1 · 莫甘娜 2 · 刺客 3**，**数字大的先动** —— 于是顺序是 **刺客 → 莫甘娜 → 莫德雷德**。取需要几张失败票，就指定前几位。

- 指定的人**可以出 success 藏自己** —— 约定给出一条线，不是拿掉一条。
- 非指定的出 fail → **具名违规 + 有界重问**，绝不静默改写。
- **奥伯伦不在里面**：他拿不到上下文，互认的坏人也不会从名单里知道他在车上。**他多出的那张失败票是故意保留的。**

**方向由牌桌主人定下了：刺客先动，莫德雷德压最后。** 这一版最初写反了（照数字表 1→3 读），已翻转，`DESIGNATE_LOWEST_PRIORITY_FIRST = false`。理由值得写下来，因为反过来读也讲得通：**刺客本来就在车上** —— 坐上一辆挂了的车，不管牌是谁出的都要被怀疑，所以他再出那一张的边际暴露很小；而**莫德雷德的全部价值是一份梅林无法反驳的干净记录**，把它花在一张换谁出都行的失败票上是最贵的买法。他是最后的预备队。

历史 seed 1 第二轮（1、2、3、4 上车）现在结算成：**2 号刺客指定**，可 fail 可 success；**3 号莫德雷德不指定，必须出成功**；**4 号奥伯伦独立**，不受约束；1 号忠臣成功。三张失败票的形状被堵死了 —— 但**两张仍然可能**（刺客 + 奥伯伦），那不是 bug，是奥伯伦这个身份的代价。

## 三、公开发言说人话

[`cognition/machine-ids.ts`](./machine-ids.ts)

M5.3 实盘每一轮每个座位都在说 `[f30][f32][f.fail2]`。**那是我写的提示defect**：发言者的事实表逐行印着编号，图例还写着「说话时可以直接指给别人看」。

修复是**结构性的**：0.6.0 的发言者事实表**根本不印编号**（`withIds` 关掉）—— 没有可抄的东西，比一条「不要抄」强。检测器是纵深防御。

**绝不静默删掉编号**：「[f30] 证明…」删四个字符会变成「 证明…」，同一个结论，证据没了。整句拒绝，重问，而且**重问说明只描述形状，不含私有内容**，所以可以安全回喂。

审计不受影响：`SentenceProvenance` 私下记录**每一句公开发言 → 授权它的证据 id**。

## 四、投票纪律（六问，不是配额）

[`cognition/vote-discipline.ts`](./vote-discipline.ts)

M5.3 Terra 那局**五辆车全部一次通过，零否车**。第二轮开出三张失败票，第三轮的车仍然带着 1 号、队长一句解释没有、7:3 通过。

六问：新约束是什么 / 这辆车和它什么关系 / 带了谁 / 队长说了什么 / 放行换到多少信息 / 连否几次。

**每一条检查都是完整性或自洽性，没有一条能拒绝一个投票。** 走完六问然后上票，通过全部检查 —— 测试里专门有一条跑十次全 approve 断言零问题。

## 五、刺杀候选排序

[`cognition/assassination.ts`](./assassination.ts)

### 诊断：为什么 M5.3 Terra 刺歪了

逐位重建那次决策的提示（`promptKey` 校验通过）之后：

**提示是错的。** 任务层写着「第四节里已经给了你坏人这边的确切身份」，第四节里**没有**。`renderOwnPrivateFacts` **从来没有渲染过 `evilRoster`** —— 0.3.0 至今任何认知版本都没有 —— 而 `fact-ids.ts` 一直在铸 `p.roster` 这个 id。**又是 M5.1 那一类：铸了 id，不渲染。**

**于是它自己推了第四个坏人。** 它从 `p.team` 知道 2、3、7，需要第四个，写下「1号 strong-evil：刺杀阶段已知其为坏人」。1 号是忠臣，奥伯伦是 4 号，被它标成 `strong-good`。

**而这个选择本身是站得住的。** 5 号推动了两辆成功车、给出了正确排除方向；四个坏人在密谈里独立地都押 5 号。没人称量的是：**最会组织的人同样可能是派西维尔或做掩护的忠臣** —— 而真梅林（9 号）拿着女神宣布过三次，恰恰因为这份显眼被打了折扣。

### 所以要排序，不要规则

八个信号，其中两个是**反信号**：`may-be-percival`、`loyal-cover`。
**每个候选必须写 `counterEvidence`** —— 只有正面没有反面的候选是断言不是评估，这正是那局亚军的形状。
**没有「刺最准的那个」这条规则。**

名单现在会被渲染（`evilRosterRendered`，0.6.0 独有，冻结版本一字不动），而且只在刺杀阶段出现 —— 时机由 `m5-4.test.ts` 的一组显式断言钉住：刺杀之前没有任何座位拿得到、奥伯伦不在互认三人的硬知识里；刺杀那一刻四个人齐全；公开回放和元数据里没有；0.5.0 在同一时刻同一个座位仍然渲染不出它，所以两局实盘逐字节可复现。

### 一次改正：刺错人是失误，不是非法动作

这一版最初把「刺一个你已经知道是坏人的人」做成了结构性错误，直接打回重问。**那是个分类错误，已经拿掉。**

裁判会照单全收这一刀 —— 它是合法的，而且是刺客能犯的最有教学价值的错误之一。**在一个研究用模拟器里，把它拒掉等于删掉观测，换来一局「失误没有发生过」的记录。**

对照组是坏人出牌协调：那一条是牌桌主人明确立的房规，所以模拟器执行它。**刺杀水平不是房规，它就是被测量的那个东西。**

所以改成观测该有的样子：

- **私下警告**（任务说明里）：名单上的人不可能是梅林，这一刀不可撤回、不能重来。
- **排到最后**：`orderedCandidates` 把名单上的人和自己一起排到候选末尾，不管模型给了多高的信心 —— 这是呈现顺序，不动 `target`。
- **放行**，不修不换不重问。
- **记下来**：`knownEvilAssassinationTarget`，一个具名的战略失误指标，从揭示身份后验算，所以对更早跑完的对局同样成立。

刺自己那一条留着，而且只因为**裁判自己拒绝**（`刺客不能刺自己`）。镜像裁判规则的结构检查是裁判规则；自己发明一条的，是在称上压手指。

刺到奥伯伦不算这一条 —— 他从来没被展示给刺客，那是浪费掉的一刀，不是本可避免的一刀。
