## 一、奥伯伦不再被告知「有一套约定」

`withCoordination` 在 0.6.0 里**只按版本门控**，而协调**正文段**是按
`observation.missionCoordination` 门控的。于是奥伯伦拿到了一个必填的 `coordination` 块，
字段说明写着「`designated` 抄第四节里给你的指定状态」—— **第四节里没有那一节。**

和 M5.4 的名单缺陷是同一个形状（说明指向一段不存在的内容），但后果不同：
**字段存在本身就在告诉他，互相不认识他的那些坏人之间有一套破坏约定。** 那正是奥伯伦
这个身份被设计成不该知道的事。

修法是让两边问同一个问题，并且**第二个条件本身也是版本门控的**，所以 0.6.0 保持原样：

```ts
const wantsCoordination =
  caps.evilCoordination &&
  (!caps.coordinationFieldGated || observation.missionCoordination !== null);
```

实测（seed 7，参考发牌，奥伯伦 4 号的任务牌回合）：

| | 字段 | 提示里有「坏人出牌协调」 | 提示长度 |
|---|---|---|---|
| `prompt-0.6.0` | `card` **`coordination`** `memoryPatch` `rationale` | 否 | 10,997 |
| `prompt-0.7.0` | `card` `memoryPatch` `rationale` | 否 | 10,746 |
| 刺客 2 号，两个版本 | `card` `coordination` `memoryPatch` `rationale` | **是** | — |

**非干涉测试**：两副只在「哪三个座位拿互认坏人身份」上不同、奥伯伦固定的发牌，
奥伯伦的 system、user 和 schema **逐字节相同**。

⚠ 一条反向的不变量**不成立，测试里专门注明了不要断言它**：协调层会渲染给有资格的
坏人在**发言和投票**回合（`observationFor` 只看 `state.proposedTeam`），那时并没有
`coordination` 字段。成立的方向只有一个：**有字段必有那一节。**

## 二、证据引用一格一个，而且必须查得到

实盘 191 次调用里有 **8 处**把多个 id 塞进一格，用全角标点当分隔符：

```
"k4:claim】【、】【k45:claim"      "f.fail1】【：】【“】【f.fail2"
"k64:side:2】【、】【k64:side:4"    "k45:claim】【、】【f15"
```

外加一处被 U+FFFC 刷屏的 `note`。**全部通过了 schema**（schema 说的是 `string`），
然后**全部解析成查无此 id**。

这比打错字更糟：`restsOnUnverified` 是从「前提解不解析得开」算出来的。一个**诚实引用**
了真 id、只是写在同一个格子里的结论，会被记成没有依据 —— 然后这个座位下一回合读自己的
记录，看到一条不成立的警告。

**不拆、不归一化。** 拆开是四行代码，而这正是 [`evidence-refs.ts`](./evidence-refs.ts)
拒绝做的事：猜出来的引用不是模型写的那一条；分隔符习惯一变，猜法悄悄改变含义，而且什么都不会失败。
走有界重问，**说明只描述形状、一个字都不回引** —— 一个查不到的 id 可能是别人的私有 id，
回引它就把引用错误变成了探测。

五种形状各有各的名字：`multiple-ids` / `full-width-delimiter` / `replacement-character` /
`blank` / `unresolvable`。指标 `malformedEvidenceReference` 按形状和字段分别计数。

### 顺带查出来的一件事：图例本身是个陷阱

新检查一上，**脚本双面直接打不了牌了**。原因是它从提示里抓 `` `[id]` ``，而
`COGNITION_INSTRUCTION_V2` 用**完全相同的记法**举例：

```
`[f12]`、`[f.fail1]`、`[c33:role]`、`[p.pair]` 这样的
```

`[p.pair]` **不是占位符，是派西维尔真实的候选对 id**。任何座位抄了它，就是在引一个
自己没有的私有 id。双面这么干了四个里程碑，什么都没坏 —— 因为一个查不到的前提只是
静默地不硬。0.7.0 拒绝它，双面立刻跑不动，缺陷才露出来。

双面已经改成只在说明层之前抓。**提示这一侧也修了，但只在 0.7.0 上**：

- `COGNITION_INSTRUCTION_V4` 的 id 段**不给任何可以抄的样例**，占位符是中文散句 ——
  抄进去解析不出 id，走的是有界重问，绝不会变成一条被接受的前提。
- **不再点名任何私有 id。** 冻结文本里写着 `p.pair` 和 `p.self`，两个都是真的、
  都属于特定身份，而那段说明是**每个座位都会收到**的。0.7.0 改成「你私有信息那一节里
  那一行开头的方括号」，让座位自己去看自己的。
- 承诺说明同理：`[k30.0]` 换成占位散句。
- 0.3.1–0.6.0 **一个字节都没动** —— 两份 instruction body 共用同一段正文，
  只有 id 那一段不同，所以两个变体不会各自漂移。

## 三、拿过女神不等于不是梅林

**两局实盘的刺客独立地犯了同一个错。** M5.3 Terra 和 M5.4 Terra 都把真梅林压了下去，
理由一模一样：

> 9 号曾公开宣布验 1 号为好人；该宣布可能来自湖中女神信息，**不能单独当作梅林线索**。

梅林两局都是 9 号，两局都活了下来。

**推理错误是可以命名的。**「有另一种解释」说明的是这条证据**不够硬**，不是它**指向反面**。
当成反面证据用，就等于立了一条有反常后果的规则 —— **女神成了防刺背心** —— 而且这条规则
好人可以故意去利用，一个会打的梅林正该去抢女神，两局的刺客都没想到这一层。

所以把问题拆开问（[`assassination.ts`](./assassination.ts) 的 `LadyAnalysis`），
每一格都能从公开记录单独回答：

- `accurateBeforeLady` —— **拿到女神之前就已经说对的那些。女神解释不了这一部分。**
- `explainedByLady` —— 确实能被那次验人解释掉的。
- `beyondLadyResult` —— 一次验人只点一个人；读对了四个，多出来的三个不算。
- `convenientCover` —— 女神是不是正好给了他掩护？
- `contradictsRoster` —— 公开宣布的结果和终局名单对不对得上？对不上是关于**他**的硬信息。

加两个信号：`accurate-before-lady`、`lady-claim-contradicts-roster`。

**只有一条规则会拒绝：** 一个候选的 `counterEvidence` **全部**归结为「他有女神信息」时打回 ——
不是因为结论错，而是因为这段推理没有内容。**没有把历史上的真梅林写死成首选**，
刺 9 号和刺 5 号在结构上都合法。

反事实测试钉住了这一点：两个行为完全相同、只有一个拿过女神的候选，检查结果一模一样。

## 四、稀释式的候选对披露

M5.3 建防泄露闸，是因为 0.4.0 的派西维尔当众说了「7、9一梅林一莫甘娜」。闸门拦得住那句。
**实盘 0.6.0 显示它拦不住这句：**

> 8、1、3只是意向车：**1、3、7、9我都看不清**

7 和 9 就是莫甘娜和梅林。四个座位，两个是真候选对。这句话不陈述任何关系，所以
`firewall.ts` 里每一条规则都放行 —— 而一个相信派西维尔诚实的刺客，拿到了一个
**含梅林的四人集合**：25% 对 1/6 的基线。**填充本身就是披露，组越小给得越多。**

[`pair-disclosure.ts`](./pair-disclosure.ts) 划一条线并守住它：

- **认知/身份分组**才算 —— 「这几个我看不清」「我重点比较 3、7、9」「这四个人里最可疑」。
- **车单和裁判事实不算** —— 「我提 8、1、3」「二轮 2、4、6、7 出了两张失败」。
  拦掉这些会让派西维尔没法打牌，而一个逼人闭嘴的闸门没人会开着。
- **两到四人、装着整对**的分组直接拒绝，**字节相同重问、不给说明** —— 说明得说出
  「别把哪两个放一起」，那就是秘密本身。
- **累积收窄**：单看「5、6、7、9」和「3、7、8、9」都不小，交集正好是 {7, 9}。
  检查会读这个座位**自己**在公开日志里说过的分组去求交 —— 从日志读而不是从记忆读，
  所以拿着产物就能复现。
- 更大的、重复的分组进遥测：`groupSizes` / `pairCoverage` / `dilutionRatio` /
  `cumulativeIntersection` / `rejections`。实盘那句的 `dilutionRatio` 是 2.0。

**发言者从头到尾拿不到真候选对**，这一层跑在墙的私有那一侧。

## 五、成立中的声称一直成立

8 号在实盘 seq 4、45、79 各报了一次派西维尔。裁判的 `standingClaims` 从 seq 4 起就一直挂着，
没人撤过、没人质疑过，后两次没有改变任何公开状态。**然后它自己的派权块把这个读成了不稳定：**

> 声称在 seq 4、45、79 重复成立又失效，稳定性不足

刺客拿这条把他的声称评成了 `weak`。**一个建模习惯 —— 因为 schema 有这个字段就复述身份 ——
变成了「这个声称很虚」的公开信号。**

**不是禁止。** 三种情况该再报：有人跳同一个身份或当面质疑（`answering-challenge`）、
牌桌在当你没报过（`resolving-ambiguity`）、退过水要重新报（`re-entering`）。
新字段 `claimPurpose` 要说明是哪一种，而且**拿公开日志核对** —— 说 `re-entering` 但从没退过水、
说 `answering-challenge` 但没人质疑过，都会被有界重问打回。

`resolving-ambiguity` 曾经是唯一日志判不了的一种 —— 也因此是可以每回合躲进去的口子。
**堵法不是加数字上限**（上限两个方向都武断：长局里两次正当澄清会被拒，短局里一次瞎编会通过），
**而是要证据**：`ambiguityEventIds` 必须指出**你上次报身份之后**发生的、够格造成歧义的公开事件 ——
别人跳身份 / 退水 / 踩你 / 新的任务结果 / 女神宣布，五类之一。一件都指不出来就是无谓重复，走有界重问。

事件列表**故意放得宽**：它不去判断牌桌是不是真的糊涂了（那是一种读法，座位有权这么读），
只拒绝「什么都没发生过」那一种。指标分开记 `acceptedAmbiguity` / `rejectedAmbiguity` /
`ambiguityEventIds`，**全部私有** —— 只进轨迹和这个座位自己的提示，公开发言里一个都不会出现。

提示层也改了：有成立声称的座位会被直接告知「**它一直成立，不要再报一次**，
想用就在话里提「按我之前说的」」。

## 六、发车自主权：只测量，不设指标

M5.4 五辆车全部一次通过、零否车。**没有为此加任何否车配额。**

那局第五轮发生的事才是对的形状：四号开场意向 1、3、5、9、10，五个人公开指出这是
第四轮那张已经开过失败票的原车，**队长在收尾时把 3 号（莫德雷德）换成了 6 号** ——
好人赢在这一换。投票纪律产出的不是更多否车，而是**发言里可核对的换车要求**，
这比否车便宜（否车推进连否计数），效果一样。

继续测：一次通过率、异议驱动的换车、挂车之后的放行率。**不设目标否车率。**

## 七、实盘结果与暂停点

`m5-5-pilot` 后来用 Terra、seed 1 跑了两次。第一局在第 10 次请求处暴露了两条运行时接线缺陷：
首次对跳没有把本回合正在提交的声称算作 standing claim；`claimPurpose` 与
`ambiguityEventIds` 虽然进入 schema，却在规范解析器里被丢弃。两条都已修复，并用那份实盘
产物逐动作回归。schema 与解析器现在另有契约测试，新增动作字段如果再被静默丢弃会直接变红。

修复后的新局走到第一轮第三次点车：8 号真派西维尔起跳，7 号莫甘娜立即对跳；前两辆车分别
以 1:9 和 3:7 被否。这是现有实盘里第一次真正出现派西维尔对跳，也是第一次出现否车。
首次运行在第 82 次请求处超时，检查点续跑成功；续跑到第 112 次请求时，provider 返回
`invalid_request_error / invalid_prompt`，该局按永久错误终止，未进入任务阶段。

这段实盘验证了：首次对跳与声称目的透传生效；social / contest 跨轮保留；公开发言没有机器
编号；候选对没有通过稀释分组泄露；认知拒绝遥测能把 14 次畸形证据引用全部留在私有层，并且
14 次都在第二次回答修好。期间出现过伪造 `system:`、`assistant to=analysis` 和广告片段等模型
退化文本，证据引用检查与防泄露闸没有让它们进入公开日志。

当前累计研究花费是 **$61.5373**。所有实盘输出、检查点和私有轨迹都在被 Git 忽略的
`research/simulator/out/`，不随代码提交。

### 暂停时已知的两条基础设施缺陷

1. 检查点保存接受的 `cognitionReports`，但没有保存 `cognitionRejections`。续跑不会改变权威
   游戏状态，却会丢掉拒绝遥测，口径不一致。
2. provider 拒绝请求时，私有轨迹只保存 `promptKey` 与长度，没有保存可供事后审计的实际提示。
   这次失败请求后来无法完整重建折叠账本，因此不能判断 400 来自账本污染、题材误判还是别的片段。

这两条在暂停前没有修。不要拿旧检查点继续那局，也不要把 `invalid_prompt` 猜成某一种原因。

## 八、下一阶段：人类高手对局语料

模型自博弈先停在这里。下一阶段不继续堆提示，而是收集高质量真人对局视频，建立可追溯的中文
语料：逐座位发言、点车、票型、任务结果、女神、声称与退水，以及复盘时公开的真实身份。
转写必须区分“当时公开信息”“玩家私有视野”“复盘答案”，不能把赛后身份倒灌进当时的盘逻辑。

这批语料首先用于总结真人高手如何组织发言、争夺焦点位、比较对跳、推动换车、协调坏人任务牌
和刺杀梅林；在形成明确标注规范与评估集之前，不直接把视频台词塞进 agent prompt。
