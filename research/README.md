# research/ — 用真实对局验证和标定推断层

这里的东西**不进 App 构建产物**，也不在 `npm test` 里跑（它们需要外部数据集）。放在仓库里是因为 `src/lib/inference/soft.ts` 的每个参数都来自这里，得能复现。

## ⚠️ 数据集的许可证

[AvalonLogs](https://github.com/WhoaWhoa/avalonlogs) **没有 LICENSE 文件**。没有声明许可证在法律上等于保留所有权利。

所以这里的做法是：

- 数据**不进仓库**（`research/data/` 在 `.gitignore` 里），也不随 App 分发
- 只从中提取**聚合统计量**（几个条件频率），写进 `soft.ts`
- 参数是对现象的测量，不是数据集的衍生作品 —— 但这是常识判断，**不是法律意见**

要商用发布前，建议联系仓库作者确认，或改用明确授权的数据源。

## 怎么跑

```bash
git clone --depth 1 https://github.com/WhoaWhoa/avalonlogs.git research/data/avalonlogs
node research/extract.js          # → research/data/games.json（12,882 局）
node research/measure-params.js   # 输出各参数的实测值
npx vitest run research/          # 证伪 + 标定（需临时把 research/ 加进 vitest include）
```

Windows 注意：AvalonLogs 的文件名含 `:`，**无法 checkout**。`extract.js` 因此直接从 git 对象库读 blob，而不是读工作区文件。

## 已经跑出来的结论

**语料**：12,882 局真人对局，含逐座位投票、每张任务牌、复盘真实身份。
人数分布 5人 3560 / 6人 3320 / 7人 2815 / 8人 1717 / 9人 857 / 10人 613。

### 1. 硬约束层的证伪（`soundness.test.ts`）

| 检验 | 结果 |
|---|---|
| 真实坏人组合是否始终存活 | **12,882 局，0 失败** |
| 「确定是好人/坏人」是否有错 | **3,729 个断言，0 错** |

硬约束层做的是不可能性断言，UI 上写着「排除了」。这一条是它唯一不允许错的地方。

顺带量出了它单独的天花板（无视野、打完整局）：

```
5人 10→7.0    7人 35→23.8    9人  84→57.2
6人 15→10.6   8人 56→40.9   10人 210→147.6
```

**排除法本身很弱** —— 这正是软证据层存在的理由。

### 2. 行为参数的实测（`measure-params.js`）

判别力（坏人率 ÷ 好人率，1.00 = 毫无信息）：

| 情形 | 好人 | 坏人 | 判别力 |
|---|---|---|---|
| 自己在车上 | 0.736 | 0.768 | **1.04** |
| 在外面，车上有坏人 | 0.396 | 0.499 | 1.26 |
| 在外面，车是干净的 | 0.598 | 0.403 | 0.67 |

两个推翻了原模型的发现：

1. **「上自己的车」不是坏人特征。** 原来手调 0.85 vs 0.50（隐含判别力 1.7），实测 1.04 —— 想让自己的车过是普通的自利，把它当成坏人特征，等于给每个上过车的人凭空加嫌疑。
2. **好人的票也带信息。** 原模型假设好人投票≈抛硬币（因为他们看不到身份）。但他们会推理：从车外看，干净车上票率 0.598，脏车 0.396。桌上的集体判断确实有效，而且这是语料里样本最大的一类。

### 3. 标定（`calibration.test.ts`）

6,441 局留出集，42,458 个座位判断：

| 方案 | Brier ↓ | LogLoss ↓ |
|---|---|---|
| 只报基线（完全不看记录） | 0.2345 | — |
| 只数可能性（纯硬约束） | 0.2234 | 0.6313 |
| 硬约束 + 手调参数 | 0.1809 | 0.5439 |
| **硬约束 + 实测参数** | **0.1712** | **0.5140** |

**`damping` 的扫描推翻了它的设计理由**。它本是防「过度自信」的搪塞值 0.5：

```
0.5 → 0.1712    1.0 → 0.1522    1.5 → 0.1526
0.8 → 0.1564    1.2 → 0.1511    2.0 → 0.1587
```

0.5 是测过的最差值。模型不是过度自信，而是系统性地**不够自信**（说 55% 时实际是 68%），damping 正是病因。最终取 **1.0** 而非经验最优 1.2：两者只差 0.7%，1.0 有清晰语义（照实使用似然），而 >1 等于无依据地放大证据。

> 用 **Brier / 可靠性曲线**而不是准确率，是因为这个产品把数字直接显示给人看，用户会照着下注。一个标定良好的 70% 比一个更「准」但过度自信的模型有用得多。

### 4. 一票在第 1 轮和第 5 轮不是一回事（`measure-by-round.js` / `ablation-by-round.test.ts`）

按轮次做消融时发现一件难看的事：**前三轮，记票让预测变差**。

```
轮次    有记票    没记票    改善
 1     0.2369    0.2324    −1.9%   ← 帮倒忙
 2     0.2246    0.2208    −1.7%
 3     0.2000    0.1987    −0.6%
 5     0.1372    0.1436    +4.5%
```

根因一测就清楚 —— 判别力随轮次单调上升：

| 轮次 | 车脏时 | 车干净时 |
|---|---|---|
| 1 | 1.07 | 0.90 |
| 3 | 1.38 | 0.65 |
| 5 | **3.72** | **0.40** |

开局那辆车谁都不知道什么，坏人上票也不花什么成本；打到第 5 轮，每张票都是满信息下的承诺。而合并出来的参数大约是第 3 轮的强度，**拿它去读第 1 轮的票，等于把噪音当证据放大**。

改成按轮次取参数之后：

```
轮次    修复前     修复后
 1     −1.9%  →   −0.5%
 3     −0.6%  →   +0.9%
 5     +4.5%  →  +11.9%
```

整体 Brier **0.1522 → 0.1461**，可靠性曲线也几乎贴上对角线（最大偏差从 0.09 降到 0.04）。

### 5. 角色层的行为证据（`measure-roles.js`）

原来的角色层只做均匀分配：阵营一旦确定，「谁是梅林」就永远是 1/6，任务成败和投票都不影响它 —— 对坏人视角来说，这正是最该有用的那个功能却完全失灵。

但梅林**看得见**，所以他的票必然和忠臣不同。从车外看的上票率：

| 角色 | 车脏时 | 车干净时 | 区分度 |
|---|---|---|---|
| 梅林 | 0.371 | 0.746 | **+0.374** |
| 派西维尔 | 0.397 | 0.603 | +0.207 |
| 忠臣 | 0.406 | 0.550 | +0.144 |
| **奥伯伦** | 0.448 | 0.464 | **+0.016** |
| 莫甘娜 | 0.478 | 0.393 | −0.085 |

排序完全符合各自能看到多少：梅林 > 派 > 忠臣。**奥伯伦那个 +0.016 是最好的旁证** —— 他是坏人却不认识队友，理论上分不出车干不干净，数据正好如此。这种排序不会是伪相关碰巧凑出来的。

接进角色层后（似然按各角色相对本阵营均值的对数比，避免与阵营层重复计分）：

```
① 开局，只有视野      2号17% 3号17% 4号17% 7号17% 8号17% 9号17%
④ 四辆车之后          2号19% 3号19%  7号 5%  8号24%
```

7 号一直给脏车上票、给干净车下票，掉到 5%；8 号投得像能看见，升到 24%。

**效果要在正确的场景下量**（`role-eval.test.ts`）。旁观者视角下找梅林几乎没提升（28.4% → 29.0%），因为阵营本身的不确定性把信号稀释了。但产品的真实场景是**坏人视角**——阵营已知，只在好人堆里挑：

| | 猜中率 | 瞎猜 | Brier |
|---|---|---|---|
| 坏人视角找梅林 | **27.1%** | 18.8% | 0.0950 |

**相对瞎猜提升 +44%。** 这才是这个功能被使用时的数字。

### 6. 一个失败的尝试：角色层按轮次拆分

角色层的轮次效应是**真实的，而且方向与阵营层相反** —— 梅林在**前期**最好认：

| 轮次 | 梅林区分度 | 忠臣区分度 | 倍数 |
|---|---|---|---|
| 1 | +0.212 | +0.028 | **7.6×** |
| 3 | +0.441 | +0.206 | 2.2× |
| 5 | +0.534 | +0.372 | 1.4× |

开局忠臣什么都不知道，而梅林已经全知道；打到最后一轮，桌上靠推理也追上来了。故事很顺，但**拆分之后实测更差**：

| | 猜中率 | Brier |
|---|---|---|
| 合并参数 | **27.1%** | **0.0950** |
| 按轮次拆分 | 26.7% | 0.0961 |

同样的拆分在阵营层有效、在角色层失效，原因是样本量：阵营层每轮拿到全场所有人的票，角色层只拿到梅林一个人的票，切成五份后**方差压过了偏差的改善**。

已回退。要做的话得先有更多对局，或者向合并值做收缩（shrinkage），而不是硬切。

## 三个必须记住的坑

- **人群不匹配是最大风险。** 这些是网上的路人局，跟面对面的朋友局不是一个人群。用错人群拟合出的参数会「自信地错」。这也是不取 1.2 的原因。
- **按局切分，不要按座位切。** 同一局里两个座位共享几乎全部证据，按座位切会泄漏。
- **牌型混杂。** 语料里坏人数与官方表不符的局（house rules）已被过滤掉。

## 还没做的

- **角色层向合并值收缩**：轮次效应真实存在（梅林前期 7.6× 好认），但硬切五份方差太大。Beta 收缩或许能拿到那部分收益。
- **保踩／意向车进模型**：语料里没有这些字段，只能等自己的复盘数据。做之前必须先有标定闭环，否则是给偏见找理论包装。
- **Beta-Bernoulli 弱先验**：把这里的在线数据当先验（等效样本量约 20 局），用户自己的复盘逐渐接管，不需要任何开关。
