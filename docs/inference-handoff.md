## 一、结论先说

你独立收敛到了 CSP4SDG 的结构，而且有一处比论文描述更克制。对照关系：

| CSP4SDG 的组成 | 你这边的对应 |
|---|---|
| 硬约束剪掉不可能的身份组合 | `constraints.ts` |
| 加权软约束给剩下的打分 | `soft.ts`（对数似然 + softmax） |
| 可解释、实时更新的 posterior | `side.ts` / `roles.ts` |
| 信息增益加权 | **原本缺失，已补，见第三节** |

**`evilFrequency` 和 `evilProbability` 分开存是这个模块最好的一个判断。** 前者是纯计数（0 和 1 是证明），后者才带行为假设；重加权永远救不回硬层删掉的世界，所以 UI 可以用不同措辞说「排除了」和「怀疑」并且都名副其实。请守住这条线。

`roles.ts` 里按角色分别算熵也是对的。用全局熵当闸门会压掉派西维尔最有价值的那个信息（他只有 1 bit 的不确定性，而侧向层还在 4.9 bit）。

### 明确劝阻：不要引入 belief propagation

GRAIL 用 BP 是因为他们的图大到解不动。**BP 是近似推断。** 我们最大 210 个世界（10 人局 `C(10,4)`），精确枚举一毫秒出精确后验——上 BP 是拿精确解换近似解。你在 `hypotheses.ts` 里已经写明了，保持。

## 二、论文的准确出处

仓库主人提到的两篇，核对后的信息：

- **CSP4SDG** — *Constraint and Information-Theory Based Role Identification in Social Deduction Games with LLM-Enhanced Inference*，**AAAI（vol 40）**，arXiv `2511.06175`。把游戏信息映射到四类约束：**evidence / phenomena / assertions / hypotheses**；硬约束剪枝，加权软约束打分；信息增益把每个假设关联到"期望熵减"；有一个闭式打分规则保证真实断言收敛到经典硬逻辑。
- **GRAIL**（Bayesian Social Deduction with Graph-Informed Language Models） — arXiv `2506.17788`。因子图 + max-product belief propagation 追踪隐藏身份，LLM 负责语言理解与生成。

**注意：以上只读了摘要与公开摘要页，未通读全文。** 涉及具体公式细节时请自行核对原文。

## 三、已补的模块：`information.ts`

新增文件，13 个测试全绿，已在 `dev` 分支（commit `27c6591`）。**不碰你正在改的任何文件。**

补的是 CSP4SDG 的信息论那一半——从"该相信什么"到"接下来该看什么"。

落点选的是**湖中女神验谁**：一局做三次、有真实代价、而且大多数人做错。

### 核心推导

验人是隐藏身份的**确定性函数**，所以期望熵减塌缩成对那个座位当前信念的二元熵，关于牌桌其余部分的项全部抵消：

```
EIG(座位) = H_b( P(他是坏人) )        H_b 在 P = 0.5 时取到最大值 1 bit
```

于是结论是：**验你最拿不准的那个人，不是你最怀疑的那个人。** 一个已经 85% 确定的座位几乎没有信息可给，而那恰恰是人本能会去验的。这条有专门的回归测试。

### 接口

```ts
rankChecks(surviving, weights, candidates): CheckValue[]   // 按 bits 降序，平手保持传入顺序
binaryEntropy(p): number
explainCheck(value): string                                 // 中文一句话理由，与算术分离
```

`weights` 传 `weighHypotheses` 的返回值；传空数组则按世界数均分。

### 它不建模的三件事（文档里写死了，UI 不要越界宣称）

1. 公开洗清一个座位的战略价值
2. 验人会把令牌传给对方，而**对方的公开宣称可能是假的**——那个宣称的价值取决于对方是否可信，是关于他的信念，不是验人这个动作的属性
3. 不做一步以上前瞻

## 四、剩下的两个缺口，以及依赖顺序

### 缺口 1：assertions 这一类没有进模型

CSP4SDG 的四类里有 **assertions**，而这个 App 正在系统性地收集它们——保踩、意向车、跳派。`soft.ts` 明确拒绝使用，理由是没有标定数据：

> 「把'骗子怎么给人打分'的猜测编码进去，等于把一个手调的偏见放在功能的正中央。」

**这个理由是对的，别急着推翻。** 它直接指向缺口 2。

### 缺口 2：参数标定的闭环

`DEFAULT_PARAMS` 每个数字都是手调的。这个 App 独有的优势是**它自己收集 ground truth**——复盘会记录每个人的真实身份和胜负。

而且**全是数数，不需要优化器**：

- `evilPlaysFail` = 坏人上车时出坏票次数 ÷ 坏人上车总次数
- `goodApproves` = 好人上票次数 ÷ 好人投票总次数
- 其余同理，都是条件频率

顺带：`damping = 0.5` 现在是拍脑袋的（你注释里承认是 "crude but honest fix"）。有了留出集，它可以**按标定误差最小来拟合**，从搪塞变成测量值。

**顺序必须是 缺口2 → 缺口1。** 先有标定能力，assertions 才有资格进模型，否则是在给偏见找理论包装。

## 五、公开数据集：可行，但优先级要调

已核实存在且字段匹配：

| 数据集 | 规模 | 字段 |
|---|---|---|
| [AvalonLogs](https://github.com/WhoaWhoa/avalonlogs) | **12,699 局**，5–10 人 | 任务、**逐座位投票**、**真实身份**、刺杀，JSON |
| [ProAvalon](https://www.proavalon.com/) | 83,000+ 条 | 含完整投票历史 |
| [Avalon-NLU](https://github.com/sstepput/Avalon-NLU) | 20 局人类对局 | 对话 + 欺骗标注 + 各阶段信念标注 |

### 关键区分：规则是通用的，行为不是

| 用途 | 依赖什么 | LLM agent 对局能不能用 |
|---|---|---|
| **A. 硬约束层证伪** | 只依赖游戏**规则** | ✅ 能，白送的覆盖 |
| **B. 拟合行为参数** | 依赖**人怎么打牌** | ❌ 不能 |

仓库主人明确不接受 LLM agent 数据当行为先验。但硬约束层检验的是规则蕴含（「2 张坏票 ⟹ 车上至少 2 个坏人」），谁在打不影响真假，所以 agent 对局在 A 里是零污染的额外覆盖。

### 建议顺序：A → D → B

**A. 用 12,699 局证伪硬约束层。** 我们的硬层做的是**不可能性断言**，UI 上写着「排除了」——错一次整个功能的可信度就没了。有真实身份标签就有标准答案：

> 对每一局的每一个时刻，断言真实的坏人组合始终存活在剩余世界里。

任何失败都是 `constraints.ts` 的真 bug。半小时写完，覆盖十几万个局面，比任何手写单测都强，而且检验的正是唯一不允许出错的那一层。**建议第一个做。**

**D. 残缺数据消融 —— 只有这个产品能问的问题。** 论文数据集是完整对局，而我们从第一天就接受残缺记录。随机丢掉 X% 的票，看后验退化多少，回答：**记多少票才回本？** 掉得少 → 告诉用户放松，别为了记全票错过听人说话；断崖 → 记录密度是核心价值，UI 该更用力推。

**B. 弱先验 + 自我修正。** 那几个参数全是二元事件概率，正好 Beta-Bernoulli 共轭：

```
后验均值 = (先验伪计数 + 自己的实际计数) / (先验总数 + 自己的实际次数)
```

用**在线真人数据**拟合，**缩放到约 20 局的等效样本量**当弱先验；用户每复盘一局就加进真实计数。于是 0 局时用在线先验，30 局左右自己的数据自然占主导，**不需要任何开关**。

### 三个必须注意的

- **人群不匹配是最大风险。** LLM agent ≠ 在线真人 ≠ 面对面的朋友。用错人群拟合出的参数是"自信地错"，比温和的手调值更糟。所以才要压等效样本量。
- **按牌型筛选，不要混着平均。** 本仓库的官方牌型：7 人局是奥伯伦、8 人局第三个坏人是爪牙（仓库主人亲自纠正过）。数据集里配置混杂，直接平均会得到一个不存在的牌局的参数。
- **按局切分训练/测试**，不要按局面切，否则同一局的信息泄漏到测试集。

### 指标应该是标定，不是准确率

这个产品**把数字显示给人看**，用户会按这个数字下注。所以主指标建议用 **Brier score / 可靠性曲线**——「说 70% 的时候他是不是真有 70% 是坏人」——排序准确率当次要指标。一个标定良好的 70% 比一个更准但过度自信的模型有用得多。

### 工程上

离线分析，不进 App 构建产物。建议 `research/`：`fetch.ts`（转成 `GameExport` 格式）、`soundness.ts`（A）、`evaluate.ts`（D + 标定）、`calibrate.ts`（B）。数据集进 `.gitignore`，使用前核对各自许可证。

## 六、一条不能破的边界

**绝不能把私有层（用户的视野、用户对别人的推测）喂进推断本身。** 那会让模型看起来很准，实际在偷看答案。

标定用的是**复盘揭示的真实身份**——那是局后信息，不是局中信息。这个区分在加了标定能力之后更容易被无意破坏，请当成硬约束。
