## 二、这个产品是什么

线下真人《阿瓦隆》的**实时记录本**，不是游戏、不是 bot。用户坐在牌桌上，用手机记别人说了什么、发了什么车、谁投了什么票。

三层，自下而上：

```
① 记录层     事件溯源，纯本地（IndexedDB），断网可用
   ↓
② 信念层     P(每个座位是什么身份)  ← 我做的，PRODUCT-V1 称 Belief Engine V1
   ↓
③ 决策层     车况风险 + rollout 胜率 → 建议   ← 别人做的，已冻结
```

外挂一块：**AI 参谋**（`src/lib/ai/`，我做的），会联网、花钱，把局势喂给 LLM 换一份分析或发言大纲。

**界面上有三个入口，别混淆：**

| 入口 | 走哪 | 联网 | 花钱 |
|---|---|---|---|
| 圆桌下「推演」开关 | `inference/` | 否 | 否 |
| 「分析局势」「帮我发言」 | `ai/` → `/api/ai` | 是 | 是 |
| 决策建议 | `decision/analyzeGame` | 否 | 否 |

## 三、信念层：设计与不可破的边界

`枚举 → 硬约束剪枝 → 行为似然加权 → 角色边际`

空间小到可以精确枚举（9 人 84 种阵营划分，10 人 210 种；角色层 10 人 151,200 种完整发牌），**所以不做近似推断**。GRAIL 那类工作用 belief propagation 是因为图大到解不动；我们一毫秒能出精确后验，上 BP 是拿精确解换近似解。

### 四条不能破的

1. **硬约束只认规则蕴含的东西。** 「第 2 轮崩了 ⟹ 车上至少 1 个坏人」是定理，「他看起来可疑」不是。UI 上写着「排除了」，所以这一层错一次整个功能就不可信。
2. **软证据只加权，永不排除。** 排除是不可能性断言，专属 `constraints.ts`。带来的保证：被证明的 0%/100% 不会被任何行为假设动摇。
3. **`evilFrequency`（数世界）和 `evilProbability`（加权）必须分开存。** 前者 0 和 1 是证明，后者带行为假设。**证明只读计数，绝不读权重。**
4. **私有层的三种东西不是一回事：**
   - **视野**（`certainty: "known"`）→ **必须进推断**，那是发牌告诉用户的合法信息
   - **推测**（`certainty: "guess"`）→ **绝不能进**，循环论证
   - **复盘真身份**（`actualRole`）→ 只能用于离线标定，进推断就是偷看答案

### 两件故意不做的

- **任务成功推不出任何人是好人**（坏人可以投成功）
- **女神当众宣布的话不作数**（公开发言，可能是谎；用户自己验人的结果走私有层）

这两条看着像证据，编进去会产生自信的错误答案。

## 四、用真实数据得到的结论（我独有的部分）

语料：AvalonLogs 12,882 局真人对局，含逐座位投票、每张任务牌、复盘真实身份。

### 已验证

| 检验 | 结果 |
|---|---|
| 硬约束层：真实坏人组合是否始终存活 | **12,882 局 0 失败** |
| 「确定是好人/坏人」断言 | **3,729 个 0 错** |
| 标定 Brier（6,441 局留出集） | 0.2345（瞎猜）→ 0.2234（纯硬约束）→ **0.1461** |

### 被数据推翻的假设 —— 这些最值钱，别让人重做一遍

1. **「上自己的车」不是坏人特征。** 我手调过 0.85 vs 0.50（隐含判别力 1.7），实测 0.768 vs 0.736 = **1.04**。想让自己的车过是普通自利，当成坏人特征等于给每个上过车的人凭空加嫌疑。
2. **好人的票也带信息。** 原假设「他们看不见身份所以≈抛硬币」。但他们会推理：从车外看干净车上票率 0.598、脏车 0.396。这是语料里样本最大的一类，被我整个丢掉过。
3. **`damping` 的设计理由是反的。** 它本是防过度自信的搪塞值 0.5，扫描后发现 0.5 是**测过的最差值**——模型系统性地**不够自信**（说 55% 时实际 68%），damping 正是病因。现取 1.0。
4. **投票的判别力随轮次单调上升**（第 1 轮 1.07，第 5 轮 3.72）。用合并参数读第 1 轮的票 = 把噪音放大成证据，实测前三轮**记票让预测变差**。已按轮次分层修复（第 5 轮改善 +4.5% → +11.9%）。
5. **同样的轮次拆分在角色层失效。** 梅林的轮次效应真实存在且方向相反（前期 7.6× 好认），但拆分后实测更差（top-1 27.1% → 26.7%）——阵营层每轮拿全场所有票，角色层只有梅林一个人的票，切五份后方差压过偏差。**已回退。** 要做得用收缩而不是硬切。

### 一个方法论教训

**评估场景选错会得出相反结论。** 角色层的行为证据在**旁观者视角**下几乎没提升（梅林 top-1 28.4% → 29.0%），差点被判定无用；但产品的真实场景是**坏人视角（阵营已知）**，那里是 **26.7% vs 瞎猜 18.8%，+42%**。阵营的不确定性会把角色信号整个稀释掉。

## 五、已知缺陷 —— 优先级最高的几件

### 1. 坏人投票用了上帝视角（`soft.ts`，我的 bug）

[research/PARAMETERS.md](../research/PARAMETERS.md) 指出的，**这条批评是对的**：

`scoreHypothesis` 按**真实**在车上的坏人数给坏人的投票打分。但有奥伯伦的局里，一个坏人看到的「干净车」可能正载着奥伯伦。拿他没有的信息解释他的行为，是设定错误而不只是分池问题。应改为按 `known_evil_on_team` 分层。

我没有修这个。**建议优先。**

### 2. 交接文档 inference-handoff.md 第六节有一处会废掉功能的错误

那份文档写着「绝不能把私有层（用户的视野、用户对别人的推测）喂进推断本身」。**「视野」不能被包含在这条禁令里** —— 见第三节第 4 条。禁掉它梅林就从 84 种收敛到 84 种，功能作废。现有代码是对的（只吃 `known`），但措辞如果被照做会出事。

### 3. 用户记的很多东西没进模型

保踩、意向车、跳派、女神的公开宣布，**全都没用**。用户在界面上认真记这些，推演层一个都不看。

保踩缺参数（公开语料没有这个字段），需要用户自己的复盘数据才能标定 —— **在有标定闭环之前别硬编参数，那是给偏见找理论包装**。

### 4. AI 层从「事实校验器」之后基本没动

`verify.ts` 只做机械核对（矛盾于证明、座位号不存在、把用户自己当嫌疑人）。没做的：worksheet 式结构化 CoT、评测集。

## 六、协作约定（CLAUDE.md 里有，但最容易踩）

- **`main` 是生产环境**，推上去 1–2 分钟用户就用上了。在 `dev` 上开发，合并由仓库主人决定。
- **提交只 `git add` 自己改过的路径**，别 `git add -A`——别人可能有写到一半的文件。
- **提交后跑 `npm run check:imports`**，只 add 自己的路径会留下悬空引用，本地永远发现不了，只有 CI 的干净 checkout 会炸。
- **不要 `taskkill /F /IM node.exe`**，会杀掉别人的 dev server。
- 高频冲突文件：`src/app/game/[gameId]/page.tsx`。动它之前先 `git pull`。
- **别让工作区长时间停在构建不过的状态** —— 多 agent 同仓，我犯过这个错。

### 数据集的法律状态

AvalonLogs **没有 LICENSE 文件**（= 保留所有权利）。现在的做法：数据不进仓库（`research/data/` 已 gitignore）、不随 App 分发，只提取聚合统计量写进代码。**商用发布前建议联系作者确认**——这是常识判断不是法律意见。
